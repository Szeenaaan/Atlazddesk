# AMC Platform

- Public product name is SupportDesk. Keep existing deployment paths, volume names, cache prefixes and browser storage keys stable during branding changes.
- Browser logins use `AccountSession`: one active session claim per user/security version, serialized with a user row lock and stored in the shared default cache. Production must use a persistent shared cache (Redis). Claim only after all required MFA factors; validate on authenticated requests and release only the owning token on logout. Idle limits are 60 seconds for Super Admin, 180 seconds for Contractor Admin, and 600 seconds for other roles. Only the authenticated, CSRF-protected `/auth/activity` endpoint renews idle time after browser interaction; polling must not renew it. Browser timers share activity across tabs and clear the interface on expiry. Closing a browser does not send logout. Cache loss invalidates claimed sessions; never silently reclaim a missing claim for a session that already has a token.

- Self-hosted per contractor: `backend-overlay/` Laravel 12/PHP, MariaDB; `frontend/` React/TypeScript/Vite; `scripts/` guarded installers; `infra/` deployment examples.
- Source in the current workspace is authoritative. Preserve local edits and use targeted changes. Never store credentials in documentation or patch payloads.
- State required user/operator actions explicitly in the final response, with the exact environment and command when known. Do not imply a database migration or deployment was applied when only source changes and isolated tests were completed. Product errors should explain the affected feature and who can resolve the issue, without vague development instructions.
- Super Admin is technical only. Contractor Admin (`admin`) owns operations and contracts with clients. Customer Admin manages own organization users; customer users see authorized own tickets. Technicians, including freelancers, see assigned work only.
- Preserve `AmcAccess` scopes, technical boundary middleware, ticket ownership, internal comment privacy, Sanctum cookie authentication, MFA and recovery. Apply scope before search/filter conditions; group OR searches.
- API routes: `backend-overlay/routes/api_v2.php`; domain models: `app/Models`; ticket mutations: `app/Services/TicketService.php`; frontend workspace: `frontend/src/App.tsx`, API client: `src/api/client.ts`.
- Assets belong to one customer and one existing ticket category. Category is the sole user-facing classification. Legacy asset type data is retained only for compatibility. Never infer category from type, matching IDs or names.
- Backend tests: from `backend-overlay`, `APP_ENV=testing DB_CONNECTION=mysql DB_DATABASE=amc_platform_test php artisan test` (add `--filter=...` for focused tests). First verify effective Laravel connection/database, including config cache and DB_URL. Never reset/migrate development or production databases or delete business records.
- Frontend production validation: from `frontend`, `npm run build` (`tsc -b && vite build`).
- Deliver patches with read-only dry run, source guards and backups. Deployment verification remains separate from local test results.
- After implementing application changes, rebuild and update the local Docker staging deployment in installation/staging, then verify service health. Preserve staging secrets and data; do not automatically migrate its database or update production. Report staging deployment separately from source tests and production deployment.

- Customer users may have zero or multiple assigned customer-owned assets; shared assets can be assigned to multiple users. Contractor Admin and own Customer Admin manage assignments. Customer-user asset reads and new ticket associations require assignment; ticket ownership remains independent.
- Contractor Admin navigation exposes Tickets and Categories as separate pages; Assets remains hidden. Contractor Admin can view and manage existing tickets, including assignment and authorized interactions, but cannot create tickets in the UI, API, service layer, or delegated customer workspace. Customer accounts retain authorized ticket creation and asset pages.
- Contractor Admin can enter an active Customer Admin workspace through User Management. Keep the web guard, MFA and account-session claim on the real Contractor Admin; apply the selected Customer Admin's scopes only after those checks. Audit the real actor with `acting_as_user_id`. Delegation must not expose profile, credentials, MFA or recovery endpoints; retain the real actor's 3-minute idle limit and provide a return action. Never take over or invalidate the customer's own login.
- Categories may be deleted only without assets or ticket history. Keep database foreign-key protection and audit deletion. Asset-count filters include inactive/retired linked assets.
- Contractor Admin User Management hides asset pickers, assignment actions and assigned-asset details; Customer Admin retains them. Delegated business authorization uses the customer scope, while existing author/operator fields and audit records use `AmcAudit::actorId($request)`. Bind delegation to the initiating cookie-authenticated actor and validate the original session claim on each request.
- Contract PDF previews use the canvas-only `PdfPreview` renderer with page navigation, without embedded browser editing/annotation tools or executing PDF actions. Keep PDF.js and its worker on the same bundled version and lazy-load them.

## Shared UI system

- Import application CSS only from `frontend/src/styles/index.css` in `main.tsx`. Cascade order is `tokens`, `screens`, `components`; do not add another override stylesheet, component-local CSS import, or `!important` rule.
- `styles/tokens.css` owns theme palettes, semantic colors, typography, spacing, radii, shadows and control dimensions. Use semantic `--color-*` variables in new components; keep meaningful error/warning/success distinctions. Use the existing `data-theme` toggle for both themes.
- Spacing follows 4px multiples: 8px label gaps, 12px action gaps, 16px field gaps, 24px sections/card padding. Controls are at least 44px tall; body/input text is 16px, labels/table/helper text at least 14px, headings 20/24px. Thin borders and focus rings are optical exceptions. Responsive boundaries are 480, 600, 800, 1152 and 1280px; CSS custom properties cannot be used inside media query conditions.
- Reuse `components/ui` Button, Field, Input, Textarea, Checkbox, Switch, FileUpload, Card, Badge, Tabs, Pagination, FilterRow and UIState. Native props, refs, form validation and event types must pass through unchanged. Do not give submit buttons a new implicit behavior.
- Reuse SearchableDropdown/SearchableSelect, SortableTable, SlidingDrawer, FeedbackToast and the native Dialog/ConfirmationDialog primitives. Dropdown menus render in the active dialog or body to avoid clipping. Dialogs must preserve focus containment, Escape handling and focus restoration. Use ConfirmationDialog for an existing confirmation flow, not to introduce new approval steps.
- Keep screen-specific layout in `styles/screens.css`; edit shared control/state rules in `styles/components.css`. Search wrappers own their border; their inner inputs must remain borderless. Keep keyboard focus visible. Avoid fixed text widths that clip long names or translations.
- System Support Configuration is vertical. Retention/cleanup UI is mounted only in System Support → Configuration. Maintenance is hidden by default and appears for Contractor Admin when `AMC_MAINTENANCE_ENABLED=true`; technicians have no independent asset directory; ticket asset context remains available within authorized assigned tickets.
- UI browser checks may mock API responses without writing business records. Report mocked browser coverage separately from real Laravel regression results; never claim unvisited screens or live authentication workflows were verified.
- Dashboard action success/errors use the shared dashboard toast host, including MFA and field-validation failures; retain useful field hints and persistent retry states. Login/MFA-login feedback stays separate. Queue and deduplicate dashboard toasts so they remain visible on mobile and do not overlap; keep dialog feedback in the active native dialog layer.

- Shared table headers use sentence case, 14px/20px text, consistent padding, and square corners. Use `InlineNotice` for inline information/errors/success; keep semantic tones and avoid nested decorative cards. Empty data tables must explain the empty result.

- Typography minimum is 14px for small/helper/status/table text, 16px/24px for body/controls, 20px/28px section headings and 24px/32px page titles. Use tokens even for chart labels; never reduce helper or responsive text below 14px. Spacing remains on the 4px grid; font sizes follow this type scale.

- Use shared `CloseButton` for dialog/drawer/popover/toast dismissal: 44px target, 24px icon, 8px padding, accessible label and visible focus. Preserve responsive mobile-navigation visibility when styling its close control.
- `Field` automatically places direct checkbox/switch controls before their copy using `.ui-choice`: fixed control dimensions, an 8px label gap and a minimum 44px label target. Do not stretch checkbox descriptions or use `space-between` for these labels. Reuse `EmailProviderFields` for SMTP/API provider fields across technical and contractor email screens; both use the shared responsive mail grid and `--form-content-width`.

- Keep TypeScript unused-local/parameter checks enabled. Run `npm run typecheck`, `npm test`, and `npm run build` from `frontend`.
- Notification list, unread count, and mark-read operations must re-check current ticket access, including reassignment and customer boundaries. Private staff events must remain hidden from customer accounts even for legacy notification records.
- Business OTPs use the default contractor provider and each user's own registered email, independently of ticket email settings; preserve separate Super Admin technical delivery. Without a selected default, legacy client-provider fallback remains available for compatibility; an inactive selected default fails closed. Shared ticket email uses only the default provider and `amc_mail_settings.notification_email`, independent of client overrides, and never individual customer recipients. Keep existing in-app recipient/privacy scopes unchanged. Queue after commit through `TicketBusinessMail`; the unique delivery ledger prevents duplicate worker sends. Never automatically replay `sending`/`uncertain` SMTP attempts, since delivery may have been accepted before acknowledgement was lost. No OTPs, credentials, bodies or uploaded files in delivery logs or ticket emails.
- Ticket mail renders escaped HTML with a protected link and plain-text alternative. Its queue connection inherits the main queue, except `sync` defaults to `database`; an optional `TICKET_MAIL_QUEUE_CONNECTION` override requires a matching worker. OTP acceptance remains synchronous. The post-commit ticket ledger is not a transactional outbox; report that distinction accurately.
- Outbound OTP emails and business/technical test emails use encrypted `SendAccountEmail` jobs, with `security` before `notifications` in worker priority. OTP code validation, login decisions and session creation remain synchronous. Queued means accepted for background processing, never proof of inbox delivery. Professional response messages must state the affected action and a useful next step; retain sanitized errors and safe request references.
- Keep queue, worker and transport terminology in operational diagnostics. User-facing email confirmations should direct the user to check their inbox and allow for delivery time, without claiming confirmed delivery. Use the same wording in API responses and UI feedback.
- SMTP configuration must verify TLS and a successful AUTH exchange before saving credentials, enabling a provider, selecting a route, or accepting a test-email request. Reject anonymous SMTP and missing credentials. Failed verification preserves saved configuration and exposes no raw SMTP errors or secrets. Use the authenticated SMTP transport for delivery; actual emails remain queued and successful authentication never proves inbox delivery.
- Guard maintenance availability responses against stale requests; every availability fetch must have a timeout and cleanup. A delayed ready response must not override a newer maintenance signal.
- Runtime security baseline: PHP 8.4.27+ within 8.4 and Node.js 24.22.1+ within 24.x. Keep Docker, CI, Composer/npm requirements and runtime checks aligned when updating security releases. See docs/deployment/runtime-security.md for guarded host updates and deployment verification; source pins do not prove a live server was upgraded.

## Assistant model selection

- Use a light or fast model for straightforward questions, small documentation edits, simple formatting, and routine read-only checks.
- Use a standard workhorse model for normal implementation, debugging, testing, and code review.
- Use a high-reasoning or ultra model only for complex security reviews, cross-system design decisions, difficult failures, or changes with substantial production risk.
- Choose the least expensive model that can complete the task reliably. Model selection does not replace tests, review, or the repository's security and deployment rules.
